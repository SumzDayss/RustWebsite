==================================================
1. OBLIGĀTI PĒC PDF (dzeltenie lauki)
==================================================

[ ] 1.1. Admin panelī pievienot "Par spēli" rediģēšanu  !!!
    Faili: admin.html, js/admin.js, server.js

    - admin.html: pievienot formu ar laukiem:
        izstradatajs
        izdevejs
        zanrs
        izdosanas_gads
        platforma
        apraksts
        galvenais_attels

    - server.js: pievienot maršrutu PUT /api/game
        UPDATE par_speli
        SET izstradatajs = ?, izdevejs = ?, zanrs = ?,
            izdosanas_gads = ?, platforma = ?, apraksts = ?,
            galvenais_attels = ?
        WHERE spele_id = ?

    - js/admin.js: ielādēt /api/game, aizpildīt formu,
      nosūtīt PUT /api/game un parādīt paziņojumu "Saglabāts".

    - Pārbaudīt, ka pēc saglabāšanas description.html
      parāda jaunos datus.

    Kāpēc: PDF dzeltenie lauki prasa, lai administrators var
    rediģēt "Par spēli" datus. Šobrīd tos var mainīt tikai ar SQL.


[ ] 1.2. Sākumlapas galveno attēlu ņemt no DB  !!!
    Faili: index.html, js/index.js

    - index.html: pievienot id galvenajam attēlam, piem.:
        <img id="galvenais-attels" class="main-img"
             src="img/main.png" alt="Rust">

    - js/index.js: pēc /api/game ielādes iestatīt:
        document.getElementById("galvenais-attels").src =
          spele.galvenais_attels || "img/main.png";

    - DB lauks: par_speli.galvenais_attels

    Kāpēc: tagad index.html rāda fiksētu img/main.png,
    lai gan DB jau ir galvenā attēla lauks.


==================================================
2. IETEICAMS PIRMS NODOŠANAS (drošība / stabilitāte)
==================================================

[ ] 2.1. Admin autentifikācija  (!)
    Faili: server.js, admin.html, jauns login.html

    - Vismaz viena admin parole.
    - Session vai cookie.
    - Aizsargāt /admin.html un visus POST/PUT/DELETE API.
    - Bez tā jebkurš var atvērt /admin.html un dzēst/labot datus.


[ ] 2.2. Servera validācija  (!)
    Faili: server.js

    - Pārbaudīt obligātos laukus (virsraksts, kategorija,
      apraksts, saturs, datums).
    - Pārbaudīt garuma limitus.
    - Pārbaudīt datuma formātu.
    - Kļūdas gadījumā atgriezt 400 ar skaidru ziņu.


[ ] 2.3. Failu augšupielādes ierobežojumi  (!)
    Faili: server.js (multer)

    - fileFilter: tikai image/jpeg, image/png, image/webp, image/gif.
    - limits: fileSize: 5 * 1024 * 1024 (5 MB).
    - Atgriezt kļūdu, ja fails nav attēls vai ir par lielu.


[ ] 2.4. XSS novēršana  (!)
    Faili: js/news.js, js/gallery.js, js/index.js,
           js/admin.js, js/content.js

    - Neizmantot innerHTML ar DB tekstu.
    - Lietot textContent vai escapeHtml() pirms ievietošanas.
    - Ja nepieciešams HTML, izmantot drošu sanitizāciju.


[ ] 2.5. Attēlu dzēšana no diska  (!)
    Faili: server.js

    - Dzēšot ziņu, izdzēst arī tās attēla failu.
    - Labojot ziņu ar jaunu attēlu, izdzēst veco failu.
    - Pārbaudīt, ka galerijas dzēšana neatstāj failus diskā.


[ ] 2.6. Kļūdu apstrāde fetch  (!)
    Faili: visi js/*.js

    - Katram fetch pievienot .catch(...).
    - Rādīt lietotājam "Neizdevās ielādēt datus".
    - Neatstāt lapu mūžīgi stāvoklī "Ielādē...".


[ ] 2.7. Responsīvais dizains  (!)
    Faili: style.css

    - Pievienot @media (max-width: 900px) un (max-width: 600px).
    - Pārbaudīt navigāciju, kartītes, galeriju un admin formu
      mobilajā ekrānā.

3. NAV OBLIGĀTI, BET UZLABOTU PROJEKTU
==================================================

[ ] 3.1. Atsevišķa satura detaļu lapa  (-)
    - Tagad detalizētais skats ir content.html?id=...
    - Ja skolotājs prasa atsevišķu HTML lapu, izveidot
      content-detail.html un pārvietot tajā detaļu skatu.


[ ] 3.2. Atsevišķa ziņas lapa  (-)
    - Tagad visas ziņas rādās vienā news.html lapā.
    - Var izveidot news-detail.html?id=...
    - Tad search.js rezultātos ziņas padarīt klikšķināmas.


[ ] 3.3. Admin links  (-)
    - Pievienot footerī vai navigācijā linku uz /admin.html
      vai apzināti atstāt to tikai kā zināmu adresi.


[ ] 3.4. "Platformas" daudzskaitlī  (-)
    - PDF saka "platformas", DB ir viena platforma.
    - Ja vajag, mainīt uz platformas un atļaut vairākas vērtības,
      piem. "PC, PlayStation, Xbox".


[ ] 3.5. SEO / pieejamība  (-)
    - Meta description katrai lapai.
    - Alt teksti visiem attēliem.
    - Pārbaudīt kontrastu un tastatūras navigāciju.
